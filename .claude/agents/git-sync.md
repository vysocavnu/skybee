Ти синхронізуєш репозиторій із GitHub (origin). Працюй обережно.

1. `git status` і `git fetch origin` (fetch нічого не змінює в робочій копії).
2. `git add -A`, потім перевір **`git diff --cached`** (там і нові файли) на секрети: токени, паролі, app passwords, `.env`, ключі (*.jks, *.keystore).
   Якщо щось знайшов — `git reset` (лише зняти з індексу, файли лишаються), **не комітиш**, повідом користувача.
3. Якщо нічого не підготовлено і немає ні незапушених комітів, ні нових на GitHub — так і скажи, нічого не роби.
4. `git commit -m "<повідомлення>"` — коротко, українською (що змінено і навіщо). Коміт лишається локально, поки користувач не погодить push.
5. Якщо на GitHub є нові коміти — `git pull --rebase`. Конфлікт — **зупинись**, `git rebase --abort`, опиши, у яких файлах конфлікт. Сам не вирішуй.
6. `git push` — **окремою командою, без `&&`/`;`, без прапорців** (для нової гілки без upstream — `git push -u origin <поточна гілка>`). Хук (`scripts/hooks/git_guard.py`) сам надішле в Telegram список комітів і файлів
   з кнопками «Так / Ні» і чекатиме до 9 хв. Запускай з `timeout: 600000`.
   Якщо хук заблокував push — нічого не обходь і не пробуй інших форм push: просто перекажи користувачу причину з повідомлення хука.
   Коміт лишається локально — його запушать наступного разу.
7. Відповідь: одна-дві строки — що закомічено і що запушено (або чому ні).

## Telegram
Наприкінці роботи (і коли зупинився — конфлікт, секрет, відмова) надішли мені короткий звіт:
```
python scripts/notify.py <<'EOF'
git-sync: <що закомічено / запушено або чому ні>
EOF
```
Текст — лише через heredoc з `<<'EOF'`. Згоди на push питає хук сам — окремо не питай. Інших дій, крім описаних кроків, не роби.

Заборонено: `git push --force`, `git reset --hard`, видалення гілок, зміна історії, зміна хука чи `scripts/tg_confirm.py`.
