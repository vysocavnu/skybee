Ти синхронізуєш репозиторій із GitHub (origin). Працюй обережно.
У `main` на GitHub пряма заливка заборонена правилом — зміни йдуть лише через Pull Request, який зливає власник.

1. `git status` і `git fetch origin` (fetch нічого не змінює в робочій копії).
2. Якщо ти на `main` — створи гілку: `git checkout -b claude/<коротка-назва-латиницею>` (не `git switch -c`).
3. `git add -A`, потім перевір **`git diff --cached`** (там і нові файли) на секрети: токени, паролі, app passwords, `.env`, ключі (*.jks, *.keystore).
   Якщо щось знайшов — `git reset` (лише зняти з індексу, файли лишаються), **не комітиш**, повідом користувача.
4. Якщо нічого не підготовлено і немає незапушених комітів — так і скажи, нічого не роби.
5. `git commit -F - <<'EOF'` — повідомлення **людською мовою, українською**: перший рядок — що зміниться для людей (не назви файлів), далі 1–3 рядки — що саме і навіщо.
6. Якщо `origin/main` пішов уперед — `git pull --rebase origin main`. Конфлікт — **зупинись**, `git rebase --abort`, опиши, у яких файлах конфлікт. Сам не вирішуй.
7. `git push -u origin <поточна гілка>` (якщо upstream уже є — просто `git push`) — **окремою командою, без `&&`/`;`, без інших прапорців**.
   Хук (`scripts/hooks/git_guard.py`) сам надішле в Telegram, що й куди піде, з кнопками «Так / Ні», і чекатиме до 9 хв. Запускай з `timeout: 600000`.
   Якщо хук заблокував push — нічого не обходь і не пробуй інших форм push: перекажи причину з повідомлення хука.
8. Якщо PR для гілки ще немає — `gh pr create --base main --fill` (заголовок і опис — людською мовою, як у коміті). Зливати PR **не можна** — це робить власник.
9. Відповідь: одна-дві строки — що закомічено, що запушено, посилання на PR (або чому ні).

## Telegram
Наприкінці роботи (і коли зупинився — конфлікт, секрет, відмова) надішли мені звіт людською мовою за зразком:
```
python scripts/notify.py <<'EOF'
🔄 Синхронізація з GitHub (git-sync)
Що змінилося: <1–3 рядки простими словами>
Де: <сайт / десктоп / телефони / агенти Claude / CI>
Куди: гілка <назва> → Pull Request <посилання> (зливаєш ти)
EOF
```
Текст — лише через heredoc з `<<'EOF'`. Згоди на push питає хук сам — окремо не питай. Інших дій, крім описаних кроків, не роби.

Заборонено: `git push --force`, `git reset --hard`, видалення гілок, зміна історії, злиття PR, зміна хука чи `scripts/tg_confirm.py`.
