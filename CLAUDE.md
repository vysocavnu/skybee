# Skybee 🐝 — інструкції для Claude

Skybee — відкритий клієнт для Bluesky (AT Protocol). Автор: vysocavnu.
Спілкуйся українською. Відповідай коротко й по суті.

## Стан проєкту
- Зараз це **веб-версія** (vanilla JS, ES-модулі, без збірки і без залежностей).
- Хостинг: GitHub Pages з гілки `main`, корінь репозиторію → https://vysocavnu.github.io/skybee
  Кожен push у `main` автоматично оновлює сайт.
- Є **десктопна версія для Windows на Electron** (`desktop/`): лише інсталятор NSIS (переносну версію автор попросив прибрати).
  Саме Electron, а не Tauri: Tauri на Windows потребує WebView2 (Edge), а в автора Edge заблокований — застосунок має нести власний рушій.
  Збирає GitHub Actions (`.github/workflows/desktop.yml`): тег `vX.Y.Z` → реліз; зміни застосунку в `main` (веб чи `desktop/`) або ручний запуск → артефакти і pre-release `desktop-test` із файлами **без ZIP** (`Skybee-Setup.exe`, `Skybee.AppImage`, `Skybee-linux-x64.tar.gz`, `Skybee.flatpak`). Автор хоче готові файли, не архіви: давати посилання на `desktop-test` / `mobile-test`, а не на артефакти.
  Інтерфейс у десктопі **оновлюється сам**: під час запуску оболонка тихо завантажує сайт із GitHub Pages у `userData/web-cache`
  і з наступного запуску показує його, якщо він новіший за збірку. Новий EXE потрібен лише при зміні `desktop/main.js` чи Electron.
  **Сама оболонка (EXE) теж оновлюється сама** (з v0.2.0): `electron-updater` при запуску й раз на 6 год читає `latest.yml` з найновішого
  GitHub-релізу, тихо качає інсталятор (прогрес на кнопці в панелі задач), питає «Оновити зараз / Пізніше»; «Пізніше» — встановиться при закритті.
  Щоб випустити оновлення: підняти `version` у `desktop/package.json`, потім або запушити тег `vX.Y.Z`, або запустити workflow вручну
  (Actions → Desktop → Run workflow, поле «version» = `vX.Y.Z`; з цієї сесії Claude тегів пушити не може) — викладе `.exe`, `.blockmap`, `latest.yml`, Linux і Flatpak.
  Встановлення на всіх користувачів (perMachine), тож Windows один раз попросить дозвіл адміністратора на оновлення.
  Закриття вікна ховає Skybee в трей (сповіщення й далі приходять; «Вийти» — у меню трею; там же «Запускати разом із Windows» → `--hidden`).
  `preload.js` — єдиний міст: `version()`, `update()`, `onLink(cb)` (посилання `skybee://`). Дозволи Electron — лише сповіщення (для Skybee), повний екран, копіювання, DRM (`setPermissionRequestHandler`);
  F12 — лише з вихідного коду або `SKYBEE_DEVTOOLS=1`; electron fuses (без RunAsNode / NODE_OPTIONS / --inspect) у `build.electronFuses`.
  Версія — у `desktop/package.json`. **Linux**: той самий workflow збирає AppImage (оновлюється сам, `latest-linux.yml`) і tar.gz,
  а з tar.gz — **Flatpak** (`flatpak/`: маніфест на `org.electronjs.Electron2.BaseApp` + zypak, `.desktop`, metainfo, іконка; README — як подати у Flathub).
  У Flatpak вимкнене і самооновлення оболонки, і завантаження вебчастини з сайту (правила Flathub) — оновлює лише Flathub. Скріншоти для каталогу — `docs/screenshots/`. Далі за планом: macOS.
- **Телефони (Android, iOS)** — `mobile/`: Capacitor 7 (та сама вебчастина в `mobile/www/`, `node scripts/dist.mjs mobile/www`). Нативні проєкти не комітяться —
  `npx cap add android|ios` створює їх у CI (`.github/workflows/mobile.yml`), іконки й заставка — `@capacitor/assets` з `mobile/assets/`.
  APK — релізна збірка, підписана ключем із секретів (`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASS`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASS`, відбиток — змінна `ANDROID_CERT_SHA256`);
  поки секретів немає — відкритим тестовим `mobile/debug.keystore` (відбиток `fb9ab4…e785`) з попередженням у CI. Ключ прописаний у `build.gradle` кроком CI (копія в `~/.android` не діяла), CI звіряє відбиток; IPA — без підпису (Sideloadly/AltStore підписують Apple ID).
  Кожна збірка оновлює pre-release `mobile-test` (Skybee.apk, Skybee-unsigned.ipa); тег `vX.Y.Z` — ще й у реліз. Вебчастина в телефоні поки не оновлюється сама — потрібна нова збірка.
  Статус-бар і нижня панель: сторінка на весь екран (edge-to-edge), відступи — CSS-змінні `--sat/--sab/--sal/--sar` (за замовчуванням `env(safe-area-inset-*)`; у CSS не писати `env(...)` напряму).
  iPhone дає їх через `env()`, на Android `native.js` бере їх з плагіна `capacitor-plugin-safe-area` (WebView там віддає 0). `adjustMarginsForEdgeToEdge` не вмикати: поля навколо сторінки стають білими.
  Значки статус-бару під тему — `@capacitor/status-bar` (`statusBarFor` у native.js, викликає `applyLook`).
  `js/native.js`: лише в Capacitor — зовнішні посилання й `window.open` → системний браузер, кнопка «Назад» Android (меню → вікно → бічне меню → крок назад → вихід); у всіх застосунках (і десктопі з сенсорним екраном) — свайп від лівого краю вправо = «Назад» (`closeTop`, стрілка `.swipeback`).

## Структура
- `index.html` — оболонка, підключає `css/style.css` і `js/app.js`
- `sw.js`, `manifest.webmanifest`, `icons/` — PWA. Service worker працює за принципом «спершу мережа» (кеш лише для офлайну)
  і обробляє кліки по системних сповіщеннях. Новий файл оболонки треба дописати в список `SHELL` у `sw.js`
- `js/api.js` — сесії кількох акаунтів (`skybee.accounts`), threadgate, postgate (заборона й від'єднання цитат), приховані відповіді, списки, фільтри контенту, паролі застосунків, приховані слова, завантаження відео через video.bsky.app, XRPC-запити з авто-оновленням токена, визначення PDS (handle → DID → PDS),
  записи (like/repost/follow/…), завантаження і стиснення зображень, facets, фіди в налаштуваннях
- `js/ui.js` — `bee(size)`: логотип-бджола (золота лінійна графіка, градієнт `--bee-hi/--bee-lo`, той самий золотий у всіх темах; дрібна — товщі лінії без візерунка), замість емодзі 🐝 усюди;
  у тостах «🐝» сам стає малюнком. Іконки (`icons/`, `favicon.ico`, `desktop/icon.png|ico`, `flatpak/icon-512.png`, вбудовані у сторінки помилок) — та сама бджола на **білому фоні** (золото трохи темніше для контрасту); при зміні іконок підняти `?v=N` у `index.html` і `manifest.webmanifest`, щоб браузер скинув кеш. Рендер постів, ембедів, rich text, акторів; модалки, меню, тости, lightbox, HLS-відео, нескінченне прокручування
- `js/compose.js` — редактор постів (гілка з кількох постів, фото + ALT, картки посилань через cardyb, цитати, відповіді, мова,
  підказки @згадок, попередження про вміст, чернетка тексту в `skybee.draft`)
- `js/views.js` — екрани: головна, фід, список, гілка, профіль, сповіщення, пошук, фіди, закладки, чати, налаштування.
  Сповіщення: чипи-фільтри `NFILTERS` (`#/notifications/<фільтр>`), заголовки днів, «вподобав(-ла) N ваших постів».
  Чат: дотик до повідомлення → аркуш (швидкі реакції + «＋», час, відповісти, перекласти, копіювати, видалити для мене);
  відповідь — справжня, полем `replyTo: {messageId}` (показується цитатою, як в офіційному); старі відповіді Skybee з `> уривок` теж показуються
- `js/more.js` — екрани: списки (створення, учасники, модераційні), стартові набори, фільтри контенту, акаунт, паролі застосунків; права колонка (фіди головної — на широкому екрані замість вкладок, `homeTabs` у views.js; «Кого почитати»)
- `js/settings.js` — налаштування: головний список розділів і всі підсторінки (`#/settings/<розділ>`); тема, колір застосунку (`skybee.color` — будь-який hex: круглі кольори `APP_COLORS` у settings.js + «＋» зі своїм кольором через `<input type=color>`, як у налаштуваннях ігор; `html.sb-theme` лише підміняє акцент `--accent`/`--accent-ink` — кнопки, перемикачі, активна вкладка, лічильники; тло лишається за темою, бджола золота), шрифт, «спокійний» режим (`applyLook`).
  Головний екран налаштувань — як у Telegram: шапка з аватаркою на кольорі профілю Skybee (`--pc` з `flair.load`, плавно переходить у тло), кнопки QR (`data-act="shareMe"` → `shareDialog`) і «Змінити»;
  інші акаунти пристрою списком із лічильником непрочитаних сповіщень (запит `getUnreadCount` від імені того акаунта, `as`), дотик — перемкнутися; «Додати акаунт»; групи `.sgroup` — заокруглені картки.
  Нічого не відкриває на bsky.app — усе робиться в Skybee
- `js/flair.js` — «оформлення» профілю, яке бачать лише користувачі Skybee: статус у бульбашці біля аватарки, трек під біо
  (кнопка «+»: пошук по каталогу iTunes без ключа, з 30-секундним уривком; або посилання — дані через song.link),
  колір сторінки профілю і його постів — **градієнт** (поля запису `color` → `color2`; лише `color` — суцільний колір), лише центральна колонка (і власна картка профілю праворуч, `flair.paint`), м’яко розмивається в бічні (готові «пігулки» `GRADIENTS` + «свій: ● → ●»; `flair.tint`, CSS `main.sb-tint` + `--sb`/`--sb2` → `--bg`/`--bg2`: на світлій темі самі кольори, на темній і в сутінках — їхні глибокі темні відтінки), іграшка-фото на банері. Зберігається в репозиторії користувача одним записом
  `io.github.vysocavnu.skybee.profile/self`; чужі читаються напряму з їхнього PDS без авторизації. Поля чужих записів перевіряються (`clean`)
- `js/sources.js` — джерела постів (підписки, фід, список, пошук, профіль) для колонок і власних стрічок; рушій «Моїх стрічок»
  (злиття джерел без повторів, ключові слова з межами слів, фільтри, сортування — усе в клієнті, без сервера фідів;
  зберігаються записом `io.github.vysocavnu.skybee.feeds/self`); сітка медіа (`tiles`)
- `js/deck.js` — «Колонки» `#/deck` (кілька колонок поруч, кожна зі своєю прокруткою, можна від імені іншого доданого акаунта,
  раз на 2 хв перевіряє нове й лише позначає ↻ крапкою (вміст сам не замінюється), на телефоні — гортання вбік; розкладка в `skybee.deck.<did>`), вибір джерела `pickSource`,
  конструктор стрічок `#/myfeeds`, `#/myfeeds/<id|new>`, перегляд `#/myfeed/<id>`
- `js/splash.js` — заставка при вході (раз за сесію, ~3,5 с, дотик пропускає): кремове небо, сонце, пагорби, луки з квітами (векторні, під комп'ютер і телефон),
  золота бджола летить і сідає над «Skybee». Вимкнена при «Зменшити анімацію» чи системному reduce motion. Імпортується першою в `app.js`, помилка в ній застосунок не зупиняє
- Реєстрація `#/signup` (`signupScreen` в app.js, `api.signup`): у **застосунках** (десктоп, Android, iOS) — лише кнопка, що відкриває в браузері сайт `#/signup?app=1`;
  після реєстрації сайт відкриває `skybee://login?handle=…`, і застосунок показує вхід із новим ніком (основний пароль; сесія посиланням не передається).
  `skybee://` реєструють: десктоп (`setAsDefaultProtocolClient`, `protocols` в electron-builder, MimeType у Flatpak; `second-instance`/`open-url` → `skybeeDesktop.onLink`),
  Android (intent-filter) та iOS (CFBundleURLTypes) — дописує CI; у JS — `onLink` з `native.js` → `handleLink` в app.js (якщо вже ввійшли — «Додати акаунт»).
  bsky.social вимагає капчу, яку проводить лише Bluesky, тож для нього сайт веде на bsky.app і дає кнопку «Повернутися в Skybee»; інші сервери — форма на сайті.
  GIF: кнопка «GIF» у редакторі, Tenor API з ключем користувача (`skybee.tenorKey`, Налаштування → Вміст і медіа), пост — зовнішнє посилання на media.tenor.com
- `js/notify.js` — системні сповіщення, поки застосунок відкритий (опитування раз на хвилину)
- `desktop/` — оболонка Electron: `main.js` (вікно, схема `app://skybee/` для вебфайлів, зовнішні посилання → системний браузер,
  один екземпляр, контекстне меню, самооновлення вебчастини: `updateWeb` обходить `index.html` → css/js → імпорти), `package.json` (налаштування electron-builder). `scripts/dist.mjs` копіює вебфайли в `desktop/web/`
  (новий файл/теку в корені треба дописати туди). Локально: `cd desktop && npm install && npm start`
- Перегляд без входу: посилання на пост чи профіль відкривається гостем (`guestRoute`, `guestShell` в `app.js`),
  запити без сесії йдуть на public.api.bsky.app, усе, що пише, просить увійти. Пункт «🐝 Посилання Skybee» в меню поста.
  Режим читання гілки: `#/profile/<h>/post/<rkey>?read` — лише пости автора одним текстом
- Як в офіційному Bluesky: мітка LIVE (`isLive`, статус `app.bsky.actor.status`, «🔴 Я в ефірі» в меню свого профілю),
  субтитри .vtt до відео (редактор + hls.js), вбудовані плеєри YouTube/Spotify/SoundCloud/Vimeo/Twitch/Apple Music (`playerOf`, iframe лише після ▶,
  вимикається в «Вміст і медіа»), сторінка хештегу `#/tag/<тег>`, фільтри пошуку (from/mentions/lang/since/until/domain),
  перегляд фото із зумом і збереженням, «↑ Нові пости» на головній, оновлення потягуванням, «Огляд» з інтересами (`interestsPref`) на порожньому пошуку,
  «Поділитися» з QR (`shareDialog`, QR через api.qrserver.com), скарга на повідомлення в чаті, створення/видалення стартових наборів `#/starter-packs/new`,
  сторонні сервіси модерації (підписка й мітки на профілі сервісу, заголовок `atproto-accept-labelers`, список у «Модерації»),
  «Показувати більше/менше такого» у фідах з `acceptsInteractions` (`sendInteractions` через проксі `<did фіда>#bsky_fg`)
- «Хто мене заблокував» `#/settings/blocked-by` (Модерація): Bluesky такого не віддає, тож список — з відкритого індексу Constellation (`api.blockedByPage`, constellation.microcosm.blue, без ключа; Clearsky закрився), дата — з rkey (TID, `api.tidDate`), профілі — з Bluesky; видалені акаунти лише рахуються
- `js/newbie.js` — «🌱 Для новеньких» `#/newcomers`: гід за матеріалами info.bsky.one і uabluerail.org, переказаний під екрани Skybee (українські стрічки — живі картки `getFeedGenerators`, модераційні списки mobik.zip та ін., поради, пошук, чати, фольклор). Пункт у меню з'являється, поки акаунту < 6 міс. (`isNewbie`, `createdAt` профілю); завжди є в Довідці
- «Перевірити оновлення» (Про Skybee, лише в десктопі, і пункт у треї): `skybeeDesktop.update()` → `checkUpdatesNow` у `desktop/main.js`
- `js/app.js` — роутер на hash (`#/profile/<handle>/post/<rkey>` тощо), навігація, глобальні дії через `data-act`

## Вигляд «Skybee 2.0 — The Social Hive»
- Шар у кінці `css/style.css` поверх наявних класів: золото лише для активного/важливого, золота смужка біля активного пункту меню й під вкладкою на телефоні,
  мотив сот (`--honey`, SVG у data-URI) — екран входу, «Колонки», порожні екрани (`empty()` в ui.js: бджола на пунктирній траєкторії), перемикачі з теплим сяйвом.
  Власний набір лінійних іконок `ico(name, size)` в ui.js (меню, нижня панель, ✏️-кнопки, розділи налаштувань): приглушені, на активному — золото зі сяйвом.
  Банер без картинки — медове світло над сотами; бульбашка статусу — «медова крапля»; траєкторія бджоли на екрані входу; «Колонки» — кнопка щільності (`skybee.deckCompact`, `.deck.compact`).

## Стилі інтерфейсу (Налаштування → Оформлення → «Стиль інтерфейсу»)
- `skybee.ui`: `auto` (за замовчуванням) | `glass` | `material` | `skybee`. Авто: iPhone/iPad → **Liquid Glass**, Android → **Material Design 3**, комп'ютер → Skybee
  (`devicePlatform()`: Capacitor `getPlatform()`, у браузері — user agent). `applyLook` ставить `html[data-ui]`; у CSS завжди `:root[data-ui=…]`
  (кнопки вибору теж мають `data-ui`, як колись `data-theme` ламав кнопку «Світла»).
- Liquid Glass: скляні шапка/картки/вікна/меню (`--glass`, blur + saturate, відблиск зверху), капсули-кнопки, сегменти iOS, перемикач iOS;
  на телефоні як в iOS 26: верх без смуги (м'яке розмиття `.topbar::before`, кнопки — скляні кружечки), вкладки в капсулі + «Пошук» окремим кругом, при прокрутці вниз капсула згортається до активної вкладки (`html.tab-min`, обробник scroll в app.js);
  нижня панель: бульбашка `.navlens` їде до активної вкладки, перетягування пальцем уздовж панелі перемикає вкладки (`placeLens` + pointer-обробник в app.js, працює в усіх стилях); ☰-меню на телефоні — на всю висоту без заокруглень;
  свої налаштування — скло `skybee.glass` (clear/normal/frost → `html[data-glass]`), плаваюча панель вкладок `skybee.glassFloat` (`html.glass-float`).
- Material 3: тональні поверхні від кольору застосунку (`--m-s1/--m-s2/--m-c`), навігаційна панель 80dp з «пігулкою» під іконкою й підписами (`.bl`),
  як у застосунках Google: розширена FAB «✏️ Новий пост» (`.fl`), що стискається до іконки при прокрутці вниз (`html.fab-min`), шапка з тлом після прокрутки (`html.scrolled`), вікна на телефоні — нижні аркуші з ручкою, налаштування — окремі плашки як в Android 16, пошук — капсула 56dp, ✓ у повзунку перемикача, «гнучка» нижня панель 64dp, сегментовані кнопки з ✓, хвиля (`.ripple`, обробник у app.js); налаштування `skybee.mTonal`, `skybee.mLabels`, `skybee.mRipple` (значення "0" вимикає).

## Перевірка без мережі
- Bluesky із хмарної сесії недоступний: екрани перевіряються Playwright-ом із підмінними відповідями XRPC (`context.route` на `https://pds.test/xrpc/*`, сесія з `pds: "https://pds.test"` у `skybee.session`) — так видно помилки консолі й графічні дефекти в усіх стилях.

## Безпека
- Токени сесій у `localStorage`, тож будь-який вставлений скрипт = захоплений акаунт. Тому: усе чуже — через `esc()`; посилання з записів — лише `http(s)`/`mailto` (`safeUrl` в ui.js);
  `index.html` має **Content-Security-Policy** (скрипти — лише свої й hls.js із jsdelivr з точною версією та `integrity`; без вбудованих `on…=` обробників і `<script>`; новий зовнішній плеєр — дописати у `frame-src`).
  На телефонах `scripts/dist.mjs` перетворює її на `<meta name="skybee-csp">`, а `native.js` вмикає одразу після старту (міст Capacitor на Android — вбудований скрипт, він має виконатися раніше).
- Адреса PDS з DID-документа — лише публічний https-хост (`api.pdsOk`). Перед надсиланням пароля на сервер не Bluesky (`api.bskyHost`) — питання з адресою сервера (раз на сервер, `skybee.trustedPds`);
  посилання `#/login?new=1&handle=…` / `skybee://login` попереджає, що його могли підкинути.
- «Оформлення» чужих профілів: обкладинка й уривок треку — лише з CDN музичних сервісів (`MEDIA_HOSTS` у flair.js), щоб власник профілю не бачив IP глядачів;
  з власних серверів (не `*.bsky.network`) — лише якщо ввімкнено «Оформлення з власних серверів» (`skybee.flairAll`, Вміст і медіа).
- Android: APK — релізна збірка (не debuggable), `allowBackup="false"`, ключ — із секретів (див. «Телефони»).
- Actions у workflow закріплені на SHA (коментар — версія).

## Помилки
- Усі помилки показуються через `errText(e)` з `js/errors.js`: людською мовою, що сталося й що робити, + технічний код у дужках
  (`network`/`offline`/`timeout`, код XRPC, HTTP-статус). Ніколи не показувати сирий `ex.message` («Failed to fetch»).
- Сторінки помилок сайту: `404.html` у корені (GitHub Pages і власний домен; адреси без `#`, як `/profile/x`, сам перекидає в застосунок),
  `offline.html` (service worker, сам перезавантажується з мережею), `errors/403|500|502|503|504.html` — для хостингу з власним доменом.
  Під власний домен: файл `CNAME` з доменом у корені + DNS; сторінки самі визначають, чи сайт у `/skybee/`, чи в корені.
